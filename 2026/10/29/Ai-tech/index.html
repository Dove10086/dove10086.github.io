注：入门定义（面向对大模型几乎零基础、但具备一定自学能力的读者）

大模型（Large Language Model，简称 LLM）

大模型就是我们平时说的“AI聊天机器人”背后的核心技术。可以把它简单理解成：一个读过海量文字、学会了语言规律的超级大脑。

目前主流的一些大模型包括：

  • Llama（Meta）
  • 通义千问（阿里）
  • 文心一言（百度）
  • DeepSeek（深度求索）
  • Gemini（Google）
  • 以及 GPT、Claude、Grok 等

它们就像不同性格、不同专长的人：

  • 有的特别擅长写文章、讲故事、逻辑清晰（文本生成能力强）
  • 有的更适合多模态（同时处理文字、图片、音频）
  • 有的推理能力突出，有的响应速度快、成本低

没有绝对的“最好”，只有“最适合当前任务”的选择。

Token（令牌）

Token 是大模型处理文字的最小单位。

  • 一个英文单词通常算 1 个 token
  • 中文一个汉字大约算 1–2 个 token
  • 标点、空格也会占用 token

为什么重要？因为：

  1. 模型每次能处理的文字量是有上限的（叫上下文窗口）
  2. 大多数收费模型都是按 token 数量计费的

可以把它理解成“大模型的字数计算单位”。

注意：Token概念，在本地部署使用的大模型不用参考

环境

这里的“环境”主要指运行大模型的地方，常见有三种：

  1. 网页/App 端（最简单）
    直接打开官网或客户端使用，例如 ChatGPT、通义千问、DeepSeek 网页版。适合普通人日常使用。

  2. API 调用
    通过代码把大模型接到自己的程序、网站、小工具里。需要一点编程基础。

  3. 本地部署
    把模型下载到自己电脑或服务器上运行（常见用 Ollama、LM Studio 等工具）。优点是数据更私密、可离线；缺点是对电脑配置有要求。

对新手来说，先从网页端开始就完全够用。

但本地部署虽然麻烦，但长期来说是最经济的

常用的“记忆”方法

大模型本身没有真正的长期记忆，每次对话默认是“失忆”的。目前常见的“让它记住”的方式有：

  • 上下文窗口：当前对话能“看见”的文字长度。窗口越大，能记住的内容越多。
  • 对话历史：平台会把前面几轮对话一起发给模型，让它“假装记得”。
  • 知识库 / RAG：把你自己的文档、笔记喂给系统，模型回答时先去查这些资料再组织语言（目前最实用的长期记忆方案）。
  • 系统提示词（System Prompt）：提前告诉模型“你是谁、要遵守什么规则”，相当于给它设定固定人格和偏好。

微调（Fine-tuning）

微调就是在已经训练好的大模型基础上，再用自己的数据继续训练，让它更懂某个领域或某种风格。

打个比方：

  • 大模型是一个已经大学毕业的人
  • 微调是让他再专门去学某个行业（医疗、法律、客服话术等），变得更专业

普通人一般不需要自己做微调，除非你有大量专业数据，并且想训练一个高度定制化的模型。对大多数人来说，用好提示词 + 知识库就已经能解决 90% 的问题。

RAG 补充说明（检索增强生成）

RAG 的全称是 Retrieval-Augmented Generation，中文常翻译成检索增强生成。

简单理解：
大模型本身“记不住”你的私有资料，也容易胡说八道。RAG 就是给它配一个外挂知识库，让它在回答前先去查资料，再根据查到的内容组织语言。

上下文引用（In-context Learning / 上下文学习）

这是大模型最神奇的能力之一：不需要重新训练，只要在对话里给它例子，它就能立刻学会。

比如你想让它按特定格式输出：

  1. 先给它看 2–3 个正确示例
  2. 再说“请按照上面的格式处理下面这段内容”

它通常就能模仿得很好。这叫少样本学习（Few-shot Learning）。

也可以直接用自然语言描述规则（零样本），效果也不错，但给例子通常更稳定。

总结给新手的建议顺序：

  1. 先随便用几个主流大模型网页版，感受差异
  2. 学会写清楚的提示词（把需求说具体）
  3. 了解 token 和上下文窗口的概念
  4. 需要长期记住资料时，再去了解知识库 / RAG
  5. 有一定基础后再考虑 API 服务器部署或本地部署
